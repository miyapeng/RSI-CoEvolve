# Fixed-budget baseline

The accepted state is a pair `(checkpoint, harness snapshot)`. For each round the loop freezes the policy, runs a bounded H-step, fixes the selected harness, delegates fresh on-policy GRPO to Slime, verifies its exported checkpoint by a new server/tool call/task rollout, then evaluates and publishes the new pair. A P-step score decrease is a valid observation. Failure to train/export/reload preserves the previous pair and all failed-attempt files. There is no trigger, Item registry, pruning, target selection or custom loss.

Four boundaries are intentionally small:

1. **Task / sandbox / reward:** `data.py` validates the existing 2,484-row JSONL and fixed manifest. `sandbox.py` uses the Tencent AGS/E2B transport in `tencent.py` with separate agent and trusted grader sandboxes. `reward.py` executes the original source-specific test scripts and parsers. Policy input is a public projection; gold/test patches and private test IDs stay outside it. Oracle diagnostics are an explicit optimization-only command.
2. **Harness search:** `search.py` reuses Self-HPO's experience builder, proposal prompt, parent check, fire gate and paired promotion. Proposer output is one complete restricted `AgentHarness` edit, with wiring and action markers. It may override real `step()` / `execute_actions()` and add `_hook_*` helpers, but cannot modify the model client, grader or host environment. All candidates may fail; the parent then remains selected. The AST gate limits the supported code API; it is not a general-purpose Python security sandbox.
3. **Policy update:** `training.py`, `train_worker.py`, `slime_rollout.py` call pinned Slime. `runtime.run_agent` invokes the same actual mini `DefaultAgent.run` and candidate methods used for H-step/dev/final generation. Native Slime captures the effective token sequences, response masks and logprobs. No Self-HPO action-after-facade mismatch remains in this path. A synchronous wrapper records the Slime update iteration; a source checkpoint reference alone does not imply that all inner iterations used identical weights.
4. **Outer loop / records:** `outer_loop.py` orchestrates these functions and saves durable stage completion records. `state.json` binds checkpoint header/index/tokenizer/sparse parameter fingerprints to the harness content hash. Resume checks configuration, source-code hashes, dataset fingerprint and accepted assets. Completed stages are reused; partial attempts remain for inspection. It does not resume in the middle of a GPU optimizer step or a half-finished candidate search.

## Dense 9B and export

`configs/baseline_9b.yaml` holds all experiment budgets. Official `qwen3.5-9B.sh` supplies Dense architecture arguments, without expert parallelism/MoE flags. Serving uses one owned SGLang process, configurable TP and `flashinfer`, rather than the original B200-only backend and 128K defaults. The generic config has 16K context; the measured A100 recipe in `configs/smoke_a100.yaml` uses 32K, serving TP1 and training TP4. Both paths use `qwen3_coder` tool parsing and `qwen3` reasoning parsing. GPU tool-call parsing and real native GRPO/export/reload were verified; see [STATUS.md](STATUS.md).

Slime loads HF directly and saves native distributed checkpoints plus HF exports. The source contains 775 tensors, including vision and MTP weights. Coding GRPO trains the language model. `checkpoint.complete_dense_export` permits copying only missing `model.visual.*` and `mtp.*` tensors into an auxiliary-only shard, and rejects any missing language-model tensor. It never fills missing LM tensors with old weights or invokes expert fusion. Parameter-change probes are bounded samples, not a full tensor checksum; reload/real rollout remains mandatory before publication. Within each P-step optimizer state is native Slime; a new outer P-step initializes its optimizer from the accepted HF policy, as an explicit baseline choice.

## Split and information boundaries

Fixed seed 42: optimization 1,987; dev 249; audit 248. Canonical repository/exact-patch components are kept together and assigned with source balance. Actual cross-split task IDs, repositories, exact patch hashes, normalized problem hashes and image references have zero overlaps. Semantic near-duplicate and repository-fork equivalence are not exhaustively resolved.

Optimization is shared by RL and H-step diagnosis. Only those gold patches can enter offline proposer evidence. Dev is adaptively reused for candidate selection and cross-evaluation, so it is not unseen validation. Audit is absent from the main loop and available only through a separate explicitly scheduled diagnostic command. Final datasets are absent from training/search; `final_eval.py` is a separate entrypoint with pinned Verified / Multilingual / Pro V2 metadata and original graders.

Inside an agent sandbox, original Git history is moved to a root-only location and a clean baseline commit preserves the seed's `git diff` submission. Commands run as an unprivileged UID without inherited host credentials; grader sandboxes receive private files separately. The SDK requests disabled agent internet; provider enforcement remains unverified. Two pinned Scale-SWE task images have been exercised live, with successful original scoring on the optimization task. This does not certify other images: `setpriv`, task environments, pre-commands and root-owned dependencies require image-specific validation. Each source image maps explicitly to a mirrored tag and expected registry digest. The host checks tag drift before creation; the provider runtime digest remains unknown and is recorded as such.

## Records and interpretation

Every completed rollout records task/source/split, policy reference, harness hash, sampling seed/parameters, image, action/observation and model request/response, submission, score, termination, tokens and latency. Missing usage/failed infrastructure is `null`, not zero. H-step proposals, raw responses, diffs, gates and selection histories are retained. P-step saves native logs, effective loss-token counts, observed finite nonzero gradient norms, reward-group variation, checkpoint inspection and reload evidence.

Per-round four-cell dev evaluation uses the same tasks/seeds/budgets for old/new policy × old/new harness. Reports are descriptive; small samples, adaptive dev reuse and environment failures limit interpretation. No score or auxiliary-removal result is labeled neural internalization. `--mode` switches the same loop among Base, H-only, P-only and HPO. `proposer_mode: self` is a separate Self-HPO-style configuration; the default API proposer stays frozen.

Run outputs are Git-ignored. JSON and JSONL records use mode 0600; use a private umask for the whole run, especially logs. Ray needs Tencent connection variables in its worker environment; secure its private job logs/runtime metadata as part of the GPU allocation. Credentials never enter task model requests or resolved project configuration.

Three original final graders accept an explicit `environment_factory` parameter. The baseline supplies the Tencent grader facade; original test construction, patch application and parsing remain intact. The legacy function names retain `orchard` for upstream compatibility, but do not import or create Orchard environments when a factory is supplied.
